# 🛡️ راهنمای جامع اتصال، رفع تحریم و تنظیمات پراکسی برای برنامه‌نویسان ایرانی

برای یک مهندس نرم‌افزار ساکن ایران، تسلط بر ابزارهای هوش مصنوعی کافی نیست؛ پیش از هر چیز باید توانایی برقراری یک اتصال پایدار، امن و کم‌تاخیر به سرورهای استریم مدل‌ها را داشته باشید. در پارادایم وایب‌کدینگ، قطع شدن جریان استریم در میانه تولید کد نه تنها باعث اتلاف وقت و سوزاندن سهمیه توکن می‌شود، بلکه فایل‌های پروژه را ناقص رها کرده و باعث به هم ریختن سورس‌کد می‌گردد.

این سند راهنمای عملیاتی و گام‌به‌گام برای عبور از سد فیلترینگ و تحریم‌های بین‌المللی در محیط‌های توسعه است.

---

<a id="sensitivity-levels"></a>
## ۱. سطوح حساسیت ابزارها به موقعیت مکانی و هویت (Tool Sensitivity Levels)

شرکت‌های حوزه هوش مصنوعی در برخورد با کاربران ایرانی به ۳ سطح کاملاً متفاوت تقسیم می‌شوند. شناخت این سطوح مانع از دست رفتن حساب‌ها یا هزینه‌های ارزی شما می‌شود:

```
┌────────────────────────────────────────────────────────────────────────┐
│                      سطوح ریسک تحریم سرویس‌های AI                      │
├────────────────────────────────────────────────────────────────────────┤
│ [سطح ۱: مسدودسازی بی‌رحمانه] Anthropic (Claude) & OpenAI (ChatGPT)    │
│  • بررسی IP + مسدودسازی شماره موبایل + تشخیص کارت اعتباری صادرکننده   │
│  • ریسک: بستن کامل اکانت و سوزاندن شارژ ارزی بدون بازگشت وجه           │
├────────────────────────────────────────────────────────────────────────┤
│ [سطح ۲: مسدودسازی شبکه / Cloudflare 403] Cursor, OpenRouter, Supabase  │
│  • بررسی اولیه موقعیت آی‌پی در لایه CDN (Cloudflare WAF)               │
│  • ریسک: با یک تغییر IP سالم یا پراکسی معتبر بدون دردسر کار می‌کند     │
├────────────────────────────────────────────────────────────────────────┤
│ [سطح ۳: انعطاف‌پذیر و توسعه‌دهنده‌محور] Google AI Studio, Groq, Ollama │
│  • دسترسی آسان به کلید API؛ بدون رفتارهای سخت‌گیرانه مسدودسازی اکانت  │
│  • ریسک: حداقل ریسک؛ ایده‌آل برای جریان کاری روزمره توسعه‌دهندگان       │
└────────────────────────────────────────────────────────────────────────┘
```

### سطح ۱: مسدودسازی کامل و بی‌رحمانه (Strict Account & Number Bans)
* **سرویس‌ها:** `Anthropic Console`، `Claude.ai`، `OpenAI Platform`.
* **مکانیسم:** این پلتفرم‌ها از سیستم‌های پیشرفته تشخیص موقعیت جغرافیایی، تحلیل فینگرپرینت مرورگر، شناسایی شماره‌های تماس مجازی (VoIP Detection) و بین‌المللی بودن کارت پرداخت استفاده می‌کنند. اگر با آی‌پی لو رفته یا بدون محافظت وارد شوید، ممکن است کل اکانت شما به همراه موجودی ارزی آن بدون هشدار مسدود (Ban) شود.
* **راهکار:** از پنل مستقیم آن‌ها با کارت‌های هویتی ایرانی استفاده نکنید. به جای آن، از طریق هاب‌های توزیع شده مانند **OpenRouter** یا **AWS Bedrock** به این مدل‌ها دسترسی پیدا کنید.

### سطح ۲: مسدودسازی ساده بر اساس IP و فایروال (IP / Cloudflare Block Only)
* **سرویس‌ها:** `Cursor`، `OpenRouter`، `v0.dev`، `Supabase`، `Bolt.new`.
* **مکانیسم:** این سرویس‌ها شما را بر اساس رنج آی‌پی یا قوانین دیوار آتش کلودفلر مسدود می‌کنند و خطای `403 Forbidden` برمی‌گردانند؛ اما اکانت شما را نمی‌بندند! با عبور از اینترنت ملی یا تنظیم یک پراکسی معتبر، سرویس بلافاصله در دسترس است.

### سطح ۳: سرویس‌های منعطف و کم‌دردسر (Developer Friendly)
* **سرویس‌ها:** `Google AI Studio (Gemini)`، `Groq`، `DeepSeek`، `Ollama (Local)`.
* **مکانیسم:** با ساده‌ترین ابزارهای دور زدن تحریم کار می‌کنند و سهمیه‌های رایگان فوق‌العاده‌ای به اکانت‌های جیمیل اختصاص می‌دهند بدون اینکه ریسک بن شدن حساب وجود داشته باشد.

<a id="dns-vs-proxy"></a>
## ۲. ریشه‌یابی فنی: چرا DNS تحریم‌شکن برای ایجنت‌های AI شکست می‌خورد؟

بسیاری از توسعه‌دهندگان می‌پرسند: *«سرویس‌هایی مانند شکن (Shecan)، الکترو (Electro)، رادار (Radar) یا 403.online برای دانلود پکیج‌های npm، docker و pip عالی کار می‌کنند؛ چرا وقتی Cursor یا Roo Code را با این DNSها باز می‌کنیم خطای اتصال یا قطعی دریافت می‌کنیم؟»*

پاسخ در تفاوت بنیادی پروتکل‌ها نهفته است:

1. **مکانیزم عملکرد تحریم‌شکن‌های DNS:**  
   این سرویس‌ها رکورد IP دامنه‌های تحریم‌شده را به سمت یک سرور واسط (SNI Proxy) هدایت می‌کنند. این روش برای درخواست‌های وب سنتی (درخواست‌های کوتاه GET/POST مبتنی بر HTTP/1.1 و دانلود فایل‌های استاتیک) عالی است.
2. **پروتکل ارتباطی ایجنت‌های مدرن هوش مصنوعی:**  
   ایجنت‌ها برای برقراری ارتباط با مدل‌ها از **Server-Sent Events (SSE)**، کانکشن‌های طولانی **WebSocket**، مالتی‌پلکسینگ **HTTP/2** و استریمینگ مداوم استفاده می‌کنند.  
3. **علت قطعی:** سرورهای DNS تحریم‌شکن به دلیل محدودیت منابع و معماری پروکسی معکوس، توانایی زنده نگه‌داشتن کانکشن‌های طولانی استریمینگ (Long-lived Streaming Connections) را ندارند، هدرهای HTTP/2 را دراپ می‌کنند و در نتیجه کلاینت شما با ارورهای `403 Forbidden`، `TLS Handshake Failed` یا قطعی ناگهانی کد روبرو می‌شود.

> [!IMPORTANT]
> **قانون طلایی:** از DNSهای ضدتحریم صرفاً برای دانلود کتابخانه‌ها و پکیج‌ها در سیستم خود استفاده کنید. برای ارتباط با ایجنت‌های هوش مصنوعی (Cursor, Windsurf, Cline, Claude Code) **همواره باید از یک تونل پراکسی پایدار (HTTP یا SOCKS5) با قابلیت استریمینگ** استفاده نمایید.

<a id="proxy-setup"></a>
## ۳. تنظیم تخصصی پراکسی در ادیتور و ترمینال (Step-by-Step Config)

برای اینکه ترافیک هوش مصنوعی شما از پراکسی عبور کند بدون آنکه اجرای لوکال هاست سرورهای داخلی (`localhost:3000`) دچار اختلال شود، تنظیمات زیر را گام‌به‌گام پیاده‌سازی کنید:

---

### ۳.۱. تنظیم پراکسی مستقیم درون VS Code و Cursor

۱. کلید ترکیبی `Ctrl + Shift + P` را فشرده و عبارت `Preferences: Open User Settings (JSON)` را باز کنید.  
۲. تنظیمات زیر را به فایل `settings.json` اضافه کنید (پورت پیش‌فرض کلاینت خود مانند v2ray، Xray، Clash یا Nekoray را جایگزین کنید):

```json
{
  // آدرس پورت لوکال کلاینت پراکسی شما (HTTP یا SOCKS5)
  "http.proxy": "http://127.0.0.1:20809",

  // اطمینان از اینکه ادیتور تمام درخواست‌های افزونه‌ها را از پراکسی عبور می‌دهد
  "http.proxySupport": "override",

  // در صورتی که کلاینت شما گواهی SSL خودامضا (Self-Signed) صادر می‌کند
  "http.proxyStrictSSL": false,

  // جلوگیری از قطعی استریم‌های gRPC در Cursor (بسیار حیاتی)
  "cursor.general.disableHttp2": true
}
```

> [!NOTE]
> اگر از پروتکل SOCKS5 استفاده می‌کنید، مقدار به صورت `"socks5://127.0.0.1:10808"` درج می‌شود؛ اما در نظر داشته باشید برخی افزونه‌ها و هسته‌های Node با پروتکل HTTP سازگاری بسیار بالاتری دارند.

---

### ۳.۲. تنظیم متغیرهای محیطی پراکسی در ترمینال (Terminal Proxy)

ایجنت‌های CLI مانند **Claude Code** و **Aider** و دستورات نصب پکیج مستقیماً از شل ترمینال اجرا می‌شوند و تنظیمات داخل `settings.json` ادیتور را نمی‌خوانند. باید متغیرهای سیستم را ست کنید:

> [!WARNING]
> **نکته کلیدی درباره Claude Code:** ابزار Claude Code از متغیرهای استاندارد `HTTP_PROXY` و `HTTPS_PROXY` پشتیبانی می‌کند اما **از پروتکل SOCKS5 مستقیماً پشتیبانی نمی‌کند**. بنابراین در ترمینال حتماً پورت HTTP کلاینت خود (مانند `20809`) را به این متغیرها اختصاص دهید.

#### در محیط ویندوز (PowerShell):
برای فعال‌سازی در سشن فعلی پاورشل:
```powershell
$env:HTTP_PROXY = "http://127.0.0.1:20809"
$env:HTTPS_PROXY = "http://127.0.0.1:20809"
$env:ALL_PROXY = "socks5://127.0.0.1:10808"

# جلوگیری از ارسال ترافیک پروژه‌های محلی به پراکسی (بسیار مهم)
$env:NO_PROXY = "localhost,127.0.0.1,::1,local.dev"

# در صورت مواجهه با خطای خودامضایی SSL در پکیج‌های نود
$env:NODE_TLS_REJECT_UNAUTHORIZED = "0"
```

برای دائمی کردن در پروفایل ویندوز کاربر:
```powershell
[System.Environment]::SetEnvironmentVariable('HTTP_PROXY', 'http://127.0.0.1:20809', [System.EnvironmentVariableTarget]::User)
[System.Environment]::SetEnvironmentVariable('HTTPS_PROXY', 'http://127.0.0.1:20809', [System.EnvironmentVariableTarget]::User)
[System.Environment]::SetEnvironmentVariable('NO_PROXY', 'localhost,127.0.0.1,::1', [System.EnvironmentVariableTarget]::User)
```

#### در محیط مک و لینوکس (Bash / Zsh):
کدهای زیر را در انتهای فایل `~/.bashrc` یا `~/.zshrc` قرار دهید:
```bash
export HTTP_PROXY="http://127.0.0.1:20809"
export HTTPS_PROXY="http://127.0.0.1:20809"
export ALL_PROXY="socks5://127.0.0.1:10808"
export NO_PROXY="localhost,127.0.0.1,::1"
export NODE_TLS_REJECT_UNAUTHORIZED="0"
```

#### در محیط خط فرمان کلاسیک ویندوز (CMD):
```cmd
set HTTP_PROXY=http://127.0.0.1:20809
set HTTPS_PROXY=http://127.0.0.1:20809
set NO_PROXY=localhost,127.0.0.1
```

<a id="troubleshooting"></a>
## ۴. خطاهای پرتکرار و راهنمای حل سریع (Troubleshooting Guide)

### ۴.۱. خطای `Connection failed` و `HTTP/2 stream closed` در Cursor
* **علت خطا:** کرسر به طور پیش‌فرض برای اتصال به کلاسترهای بک‌اند خود از پروتکل gRPC روی بستر HTTP/2 استفاده می‌کند. بسیاری از فایروال‌ها یا هسته‌های واسط پراکسی، جریان‌های مالتی‌پلکس HTTP/2 را مسدود یا پکت‌های آن را به عنوان ناهنجاری دراپ می‌کنند.
* **راه حل قطعی:**
  ۱. در تنظیمات Cursor (`Ctrl + ,`) عبارت `HTTP/2` را جستجو کنید.
  ۲. تیک گزینه **Cursor: Disable Http2** را فعال کنید (یا در `settings.json` کلید `"cursor.general.disableHttp2": true` را اضافه کنید).
  ۳. نرم‌افزار Cursor را یک بار به صورت کامل ببندید (از Task Manager یا بستن کامل پنجره) و مجدداً باز کنید. با این کار، کرسر به HTTP/1.1 سوییچ کرده و استریم‌ها بدون قطعی جاری می‌شوند.

---

### ۴.۲. خطای `Rate Limit Exceeded` یا کد وضعیت `429` روی آی‌پی‌های اشتراکی
* **علت خطا:** وقتی از کانفیگ‌های اشتراکی یا عمومی VPN استفاده می‌کنید، هزاران کاربر دیگر نیز با همان IP عمومی به سرورهای کلودفلر و هوش مصنوعی متصل می‌شوند. فایروال این پلتفرم‌ها به دلیل حجم بالای ترافیک از آن آی‌پی، موقتاً درخواست‌ها را ریجکت کرده و خطای 429 بازمی‌گرداند.
* **راه حل قطعی:**
  ۱. در نرم‌افزار پراکسی خود، سرور (Node) را به یک کشور یا لوکیشن دیگر سوییچ کنید تا IP شما تغییر کند.
  ۲. به جای استفاده از سهمیه آی‌پی مشترک در وب، از **افزونه Roo Code با کلید API اختصاصی** (مثلاً Google Gemini یا OpenRouter) استفاده کنید. در این حالت، محدودیت نرخ مصرف (Rate Limit) بر اساس کلید خصوصی شما محاسبه می‌شود، نه آی‌پی مشترک!

---

### ۴.۳. گیر کردن در لوپ تایید هویت و چالش کلودفلر (Turnstile / Captcha Loop) در زمان لاگین Cursor
* **علت خطا:** در زمان ورود اولیه به کرسر (Login with GitHub / Google)، مرورگر داخلی ادیتور در مواجهه با چالش تایید انسانی Cloudflare دچار اختلال می‌شود.
* **راه حل:**
  ۱. لینک لاگین را از کرسر کپی کرده و در مرورگر اصلی خود (Chrome/Firefox) که به پراکسی تمیز متصل است باز کنید.
  ۲. پس از تایید هویت، روی دکمه `Open Cursor` کلیک کنید یا توکن نشست را مستقیماً وارد نمایید.

---

### ۴.۴. خطای اعتبارسنجی گواهی SSL (`SELF_SIGNED_CERT_IN_CHAIN` / `UNABLE_TO_VERIFY_LEAF_SIGNATURE`)
* **علت خطا:** برخی آنتی‌ویروس‌ها یا برنامه‌های پراکسی محلی، ترافیک HTTPS را برای بازرسی بسته باز می‌کنند و گواهی امنیتی بومی خود را قرار می‌دهند که توسط Node.js شناخته‌شده نیست.
* **راه حل:**
  * در VS Code / Cursor: در `settings.json` مقدار `"http.proxyStrictSSL": false` را قرار دهید.
  * در شل ترمینال (برای Claude Code و اسکریپت‌های npm): متغیر محیطی `NODE_TLS_REJECT_UNAUTHORIZED="0"` را تنظیم کنید.

---

### ۴.۵. اختلال در اجرای لوکال هاست (`ERR_CONNECTION_REFUSED` در سرور محلی)
* **علت خطا:** ارسال ناخواسته درخواست‌های `localhost:3000` به سرور پراکسی خارج از کشور.
* **راه حل:** اطمینان حاصل کنید که متغیر `NO_PROXY` با مقدار `localhost,127.0.0.1,::1` در تنظیمات سیستم یا ترمینال تعریف شده باشد.

<a id="checklist"></a>
## 📋 چک‌لیست پایداری کانکشن وایب‌کدینگ در ایران

قبل از شروع کار بر روی هر پروژه مهم، این چک‌لیست ۵ مرحله‌ای را مرور کنید:

- [ ] پورت محلی کلاینت پراکسی فعال و تست شده است (مثلاً تست در مرورگر با سایت `ipinfo.io`).
- [ ] در تنظیمات Cursor، گزینه `disableHttp2` حتماً برابر `true` است.
- [ ] مقدار `NO_PROXY` روی ترمینال و ادیتور برای `localhost` تعریف شده تا پورت‌های سرورهای محلی مسدود نشوند.
- [ ] برای ایجنت‌های ترمینالی مانند Claude Code از آدرس پورت HTTP کلاینت (مانند `20809`) استفاده شده است.
- [ ] یک کلید رزرو و پشتیبان (Fallback API Key) از Google Gemini Flash در افزونه Roo Code آماده دارید تا در صورت قطع شدن اکانت‌های اصلی، پروژه متوقف نشود.
