# 🌐 سازنده‌های فول‌استک ابری و ابزارهای تولید رابط کاربری (AI Web Builders)

سازنده‌های وب نسل نوین (AI Web Builders)، نسل جدیدی از محیط‌های توسعه ابری هستند که پارادایم ساخت نرم‌افزار را دگرگون کرده‌اند. به جای آنکه ساعت‌ها صرف راه‌اندازی بویلرپلیت‌ها (Boilerplates)، نصب کتابخانه‌های UI، پیکربندی تایپ‌اسکریپت و تنظیم وب‌پک یا Vite کنید، تنها با یک پرامپت چندخطی یا آپلود یک طرح دستی، یک نرم‌افزار کامل و تعاملی درون مرورگر دریافت می‌کنید.

در این راهنما، مهم‌ترین پلتفرم‌های این حوزه، نقاط قوت و ضعف آن‌ها، و به‌ویژه **ورک‌فلو طلایی انتقال پروژه (The Golden Handoff Workflow)** را بررسی می‌کنیم.

---

<a id="v0"></a>
## ۱. پلتفرم v0.dev (محصول تحول‌آفرین شرکت Vercel)

پلتفرم **v0** توسط تیم ورسل (خالق Next.js) مهندسی شده و تخصصی‌ترین ابزار حال حاضر جهان برای تولید رابط‌های کاربری مدرن در اکوسیستم ری‌اکت به شمار می‌رود.

### ساختار و استک خروجی:
* **فریم‌ورک پایه:** Next.js (نسخه App Router)، React و TypeScript.
* **استایل‌دهی و کامپوننت‌ها:** Tailwind CSS به همراه کامپوننت‌های استاندارد و دسترسی‌پذیر **shadcn/ui** و آیکون‌های Lucide.
* **معماری کد:** کامپوننت‌های مستقل، ماژولار و تمیز که به سادگی در فایل‌های پروژه‌های موجود کپی می‌شوند.

### بهترین روش‌ها و ترفندهای کار با v0:
1. **طراحی واکنش‌گرا و سازگاری با زبان فارسی (RTL First):**  
   هنگام نوشتن پرامپت در v0، صراحتاً قوانین راست‌چین را یادآوری کنید:
   ```text
   Build a modern analytics dashboard for Iranian users. 
   Apply full RTL layout using Tailwind CSS logical properties (ms-*, me-*, start-*, end-*). 
   Use Vazirmatn font styling and ensure numbers and tables display cleanly in Persian.
   ```
2. **استفاده از اسکرین‌شات و طرح‌های بصری (Image to Code):**  
   تصویر یک طرح دستی روی کاغذ، وایرفریم یا اسکرین‌شات از محصول رقیب را ضمیمه کنید و بگویید: «این ساختار را با تم دارک، کامپوننت‌های کارتی shadcn و جدول داده‌های فیلترپذیر پیاده کن».
3. **ویرایش موضعی با ابزار انتخاب (Block Selection):**  
   برای اصلاح یک دکمه یا کارت، هرگز کل صفحه را مجدداً جنریت نکنید! با ابزار Selector روی بخش مورد نظر کلیک کرده و تنها پرامپت اصلاحی برای همان کامپوننت بفرستید تا سهمیه روزانه هدر نرود.

#### چه زمانی استفاده کنیم؟
* زمانی که به لندینگ‌پیج‌های فوق‌العاده شیک، داشبوردهای مدیریتی مدرن و کامپوننت‌های فرانت‌اند استاندارد Next.js/Tailwind نیاز دارید.
* زمانی که می‌خواهید یک طرح فیگما را در چند دقیقه به کدهای React آماده کپی تبدیل کنید.

#### چه زمانی استفاده نکنیم؟
* پروژه‌هایی که نیازمند دیتابیس رابطه‌ای عمیق، کرون‌جاب‌های پس‌زمینه، احراز هویت پیچیده چندنقشی یا اتصال مستقیم به درگاه‌های پرداخت هستند (v0 ژنراتور رابط کاربری است، نه بستر کامل بک‌اند).

## ۲. پلتفرم‌های فول‌استک: Lovable در برابر Bolt.new

این دو ابزار مفهوم «تولید رابط کاربری ساده» را پشت سر گذاشته و وب‌اپلیکیشن‌های کامل فول‌استک به همراه دیتابیس و لاجیک‌های تجاری تولید می‌کنند.

```
┌──────────────────────────────────────┬──────────────────────────────────────┐
│             Lovable.dev              │               Bolt.new               │
├──────────────────────────────────────┼──────────────────────────────────────┤
│ • تمرکز بر وب‌اپلیکیشن‌های پروداکشن    │ • اجرای کامل WebContainer در مرورگر   │
│ • ادغام عمیق و اتوماتیک با Supabase  │ • پشتیبانی از هر فریم‌ورک npm و Node  │
│ • تولید کدهای تمیز و استاندارد گیت   │ • راه‌اندازی آنی سرورهای Express/Vite │
│ • ایجاد خودکار جداول و لاگین کاربری │ • تست زنده و سریع پکیج‌های متن‌باز    │
│ • همگام‌سازی دوطرفه با GitHub        │ • اتصال و استقرار مستقیم روی Netlify │
└──────────────────────────────────────┴──────────────────────────────────────┘
```

---

<a id="lovable"></a>
### ۲.۱. لاوبل (Lovable.dev) - متخصص وب‌اپلیکیشن‌های واقعی

* **یکپارچگی خودکار با Supabase:**  
  وقتی به Lovable می‌گویید «یک سیستم ثبت‌نام کاربر با قابلیت ذخیره وظایف و آپلود فایل بساز»، این ابزار مستقیماً به حساب Supabase شما متصل شده، جداول دیتابیس Postgres، سیاست‌های امنیتی دسترسی به سطرها (Row Level Security - RLS) و متدهای احراز هویت را به صورت خودکار ایجاد می‌کند.
* **همگام‌سازی دوطرفه با گیت‌هاب (2-Way GitHub Sync):**  
  هر تغییری در چت Lovable مستقیم به عنوان کامیت روی ریپازیتوری گیت‌هاب شما می‌نشیند؛ و اگر کدی را به صورت محلی ویرایش و Push کنید، لاوبل تغییرات را تشخیص داده و ادامه‌اش را بر همان مبنا کد می‌زند.

#### چه زمانی استفاده کنیم؟
* ساخت MVPهای کاربردی که به دیتابیس، سیستم ورود/خروج کاربران، جداول ارتباطی و ذخیره فایل نیاز دارند.
* تیم‌های کوچکی که می‌خواهند از روز اول سورس‌کد پروژه مستقیماً در ریپازیتوری گیت‌هاب آن‌ها نگهداری شود.

#### چه زمانی استفاده نکنیم؟
* زمانی که کردیت‌های آزمایشی شما تمام شده و نمی‌خواهید ماهیانه هزینه‌های سنگین دلاری برای چت‌های طولانی پرداخت کنید (باید طبق ورک‌فلو طلایی ادامه کار را محلی انجام دهید).
* پروژه‌هایی که دیتابیس محلی (MySQL/Postgres داخلی) دارند و نباید داده‌ها در Supabase ابری ذخیره شوند.

---

<a id="bolt"></a>
### ۲.۲. بولت (Bolt.new by StackBlitz) - موتورخانه کانتینری در مرورگر

* **تکنولوژی انقلابی WebContainers:**  
  بر خلاف سایر ابزارها که کد را در سرور ابری رندر می‌کنند، Bolt یک کانتینر کامل Node.js را درون مرورگر شما اجرا می‌کند. به این معنی که می‌تواند پکیج‌های سنگین npm را نصب کند، اسکریپت‌های بیلد را اجرا نماید و سرورهای Express یا Fastify را به صورت زنده بالا بیاورد.
* **انعطاف‌پذیری استک:** محدود به Next.js نیستید؛ می‌توانید از Vite + React، Vue، SvelteKit، Nuxt، Astro و NestJS استفاده کنید.

#### چه زمانی استفاده کنیم؟
* تست سریع ایده‌های فول‌استک و آزمایش لایبرری‌های npm بدون نصب حتی یک پکیج روی سیستم محلی.
* فریم‌ورک‌های متنوع فرانت‌اند (Vue, Svelte, Astro) که در سایر ابزارها پشتیبانی ضعیف‌تری دارند.

#### چه زمانی استفاده نکنیم؟
* شرایطی که اینترنت شما پینگ بالا دارد یا سشن‌های وب‌سوکت قطع و وصل می‌شوند؛ وب‌کانتینر به ارتباط پایدار حساس است.

## ۳. محیط‌های توسعه ابری: Replit Agent و Project IDX

اگر سخت‌افزار قدرتمندی در دسترس ندارید، یا تمایل دارید از طریق تبلت و موبایل کدنویسی کنید، این دو بستر گزینه‌های اصلی هستند:

---

<a id="replit-agent"></a>
### ۳.۱. ریپلیت ایجنت (Replit Agent)
* **عملکرد کاملاً خودمختار:** ریپلیت ایجنت فرآیند کامل یک مهندس نرم‌افزار را شبیه‌سازی می‌کند: تعریف وابستگی‌ها، ساخت فایل‌ها، نصب پکیج‌ها، حل ارورها و استقرار نهایی با آدرس عمومی اینترنتی (`.replit.app`).
* **چه زمانی استفاده کنیم؟** استقرار فوری و اشتراک‌گذاری دمو با مشتریان و سرمایه‌گذاران بدون درگیری با سرور و داکر.
* **چه زمانی استفاده نکنیم؟** توسعه‌دهندگان بدون پرداخت ارزی؛ این ایجنت نیازمند اشتراک Replit Core بوده و نسبت به تغییر مداوم IP حساس است.

---

<a id="project-idx"></a>
### ۳.۲. پروجکت آی‌دی‌ایکس (Project IDX / Firebase Studio - گوگل)
* **محیط ابری مبتنی بر Nix و Code-OSS:** محصول مدرن گوگل برای برنامه‌نویسی وب، فلاتر و موبایل در فضای ابری.
* **دسترسی داخلی به هوش مصنوعی گوگل:** با مدل‌های Gemini Code Assist ادغام شده و سهمیه‌های مناسبی به توسعه‌دهندگان می‌دهد.
* **چه زمانی استفاده کنیم؟** پروژه‌های مالتی‌پلتفرم (وب + فلاتر/اندروید) و دسترسی آسان از طریق حساب جیمیل بدون حساسیت‌های بن حساب.
* **چه زمانی استفاده نکنیم؟** کارهای آفلاین یا زمان‌هایی که به ابزارهای CLI پیشرفته محلی نیاز دارید.

<a id="golden-handoff"></a>
## 🚀 ورک‌فلو طلایی انتقال پروژه (The Golden Handoff Workflow)

یکی از بزرگ‌ترین اشتباهات و تله‌های مالی در وایب‌کدینگ این است که توسعه‌دهنده سعی کند **۱۰۰٪ کل پروژه** را درون Lovable یا Bolt کد بزند!  
از پیام دهم به بعد، کردیت‌های ابزار تمام می‌شود، هزینه‌های ارزی نجومی می‌گردد و ایجنت وب در حل باگ‌های جزئی بک‌اند یا اتصال سرویس‌های بومی ایران (درگاه پرداخت، پنل پیامک و تقویم شمسی) دچار گیجی و خطاهای پرهزینه می‌شود.

### استراتژی مهندسی: قانون ۷۰ / ۳۰
```
┌──────────────────────────────────────┐          ┌──────────────────────────────────────┐
│      گام ۱: وب‌بیلدر ابری (۷۰٪ کار)      │          │     گام ۲: ادیتور محلی (۳۰٪ کار)      │
│         (v0 / Lovable / Bolt)        │          │       (Cursor / Roo Code / CLI)      │
├──────────────────────────────────────┤  گیت‌هاب  ├──────────────────────────────────────┤
│ • ساخت اسکلت اولیه و پروتوتایپ UI    │ ───────> │ • یکپارچه‌سازی سرویس‌های پرداخت محلی │
│ • کامپوننت‌های ریسپانسیو و استایل‌ها │ (Export) │ • قوانین امنیتی، کش و لاجیک‌های عمیق  │
│ • ساخت جداول و شمای اولیه دیتابیس    │          │ • پیامک OTP، تقویم شمسی و احراز هویت │
│ • استفاده از کردیت‌های روزانه رایگان │          │ • استفاده از API ارزان یا رایگان     │
└──────────────────────────────────────┘          └──────────────────────────────────────┘
```

---

### راهنمای گام‌به‌گام پیاده‌سازی ورک‌فلو طلایی:

#### گام ۱: ساخت هسته بصری در وب‌بیلدر ابری (Lovable یا Bolt)
1. با استفاده از سهمیه رایگان در Lovable یا Bolt.new، ایده محصول خود را پرامپت دهید.
2. روی کامپوننت‌ها، صفحات اصلی (Home, Dashboard, Settings, Profile) و فرم‌های ورودی تمرکز کنید.
3. اگر از Lovable استفاده می‌کنید، اجازه دهید ساختار اولیه جداول Supabase را با متغیرهای لازم بسازد.

#### گام ۲: انتقال تمیز به گیت‌هاب (GitHub Sync & Handoff)
1. در داشبورد وب‌بیلدر، گزینه **Connect to GitHub** یا **Export to Repo** را بزنید.
2. پروژه را در یک ریپازیتوری جدید (مثلاً `vibe-saas-core`) کامیت و پوش کنید.
3. لینک ریپازیتوری گیت‌هاب را کپی کنید.

#### گام ۳: کلون کردن در محیط محلی (Local Setup)
ترمینال سیستم محلی خود را باز کرده و پروژه را دریافت کنید:

```bash
git clone https://github.com/your-username/vibe-saas-core.git
cd vibe-saas-core
npm install
```

#### گام ۴: تحویل پروژه به دستیار محلی (Cursor یا Roo Code)
1. پروژه را در Cursor یا VS Code باز کنید.
2. از پوشه [`03-rules`](../03-rules) فایل قوانین پروژه متناسب با استک (مانند قوانین React/Next.js) و استاندارد فارسی [`persian-rtl-standard.md`](../03-rules/persian-rtl-standard.md) را به پروژه اضافه کنید.
3. در کامپوزر کرسر یا چت Roo Code، پرامپت تحویل را اجرا کنید:
   ```text
   Review this project structure generated by Lovable/Bolt:
   1. Clean up redundant dependencies in package.json.
   2. Ensure all environment variables are documented in .env.example.
   3. Maintain clean modular code and respect the RTL guidelines in .cursorrules.
   ```

#### گام ۵: پیاده‌سازی نیازمندی‌های بومی ایران در محیط محلی
حالا ۳۰٪ باقیمانده کار را که وب‌بیلدرهای خارجی توانایی پیاده‌سازی بهینه آن را ندارند، در سیستم خود با کلیدهای رایگان یا ارزان انجام دهید:
* **درگاه پرداخت بانکی (Zarinpal / IDPay):** روت‌های `/api/payment/request` و `/api/payment/verify` را با شبیه‌سازی درگاه پیاده‌سازی کنید.
* **احراز هویت پیامکی (SMS OTP):** سرویس ارسال پیامک با کاوه‌نگار یا قاصدک را اضافه کنید.
* **تقویم و تاریخ جلالی:** جایگزینی تاریخ‌های میلادی با کتابخانه‌های استاندارد شمسی (مانند `date-fns-jalali`).

| :--- | :--- | :--- | :--- | :--- | :--- |
| **v0** | بسیار سریع | **فوق‌العاده تمیز و استاندارد (A+)** | ضعیف (صرفاً UI و Mock Data) | سهمیه کردیت روزانه | نیازمند تغییر IP برای لایه Cloudflare |
